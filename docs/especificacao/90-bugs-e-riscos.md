# Bugs confirmados — visão geral

> Parte da especificação da API (ver [README](README.md)). Lista de triagem: cada linha resume um bug já confirmado lendo o código (não uma suspeita). O detalhe completo — trecho, mecanismo, e por que está confirmado — está no arquivo de origem, pela coluna "Arquivo". O ID é o mesmo usado na tabela de regras daquele arquivo; comece a implementação do teste por ele (`it("AGE-016 — ...")`).

**Total: 45 bugs confirmados** nesta rodada de especificação (7 críticos, 23 importantes, 15 menores) — nenhum foi corrigido ainda; esta etapa é só documentação. Vários já eram suspeitados antes desta especificação (marcados "já conhecido" abaixo); a maioria foi encontrada nesta rodada.

## Como usar esta lista

1. Ao implementar os testes, comece pelos **críticos** — cada um é um teste de INTEGRAÇÃO que hoje FALHARIA se escrito corretamente (é esse o ponto: o teste primeiro confirma o bug falhando, a correção depois faz ele passar).
2. Vários bugs compartilham causa-raiz (ex.: FIN-010/FIN-017 são o mesmo erro de fuso em dois lugares; AGE-009/CFG-026 são o mesmo `findDurationInputs` visto de dois ângulos) — corrigir a causa comum resolve as duas entradas ao mesmo tempo, mas cada uma continua precisando do próprio teste (são efeitos observáveis diferentes).
3. Nenhum destes 45 itens foi corrigido nesta etapa — é documentação. Ver [99-perguntas-em-aberto.md](99-perguntas-em-aberto.md) para os comportamentos que podem ser intencionais (não estão nesta lista de bugs).
